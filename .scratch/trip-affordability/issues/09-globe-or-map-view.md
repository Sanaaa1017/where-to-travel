# 09 — 地球儀 / 地圖視覺化

**What to build:** 除了清單之外，讓 Traveler 在地球（或地圖）上看到自己去得起哪裡——去得起的國家與差一點的國家用不同顏色標示。

「出國逃離」這件事本身是有畫面的，一份表格傳達不了。這張票要補的是那個畫面。

**Blocked by:** 05

擋在 05 之後是刻意的：要先有 20 國的真實資料，才看得出視覺化實際長什麼樣，也才有足夠依據決定要地球儀還是平面地圖。在只有 3 個種子國家的階段做這個判斷會判斷錯。

**Status:** needs-info

**待決定：地球儀 vs 平面地圖。** 兩者都可行，取捨如下：

- **地球儀**（three.js / globe.gl 之類）情緒感最強，可轉動探索，貼合「逃離」的主題。代價是函式庫體積大、任一時刻有半個地球看不見、手機上操作較吃力，而 08 明確要求照顧手機情境。
- **平面地圖**（SVG world map / Leaflet）一眼看完所有國家，容易標註金額，體積小、手機友善。情緒感較弱。

兩者都需要國家輪廓資料（Natural Earth GeoJSON，公有領域），並將 Destination 的 id 對應到輪廓資料的國碼。

- [ ] 決定地球儀或平面地圖，並記錄選擇的理由
- [ ] Affordable 與 Shortfall 的 Destination 以不同顏色區分
- [ ] 點選一個國家能看到它的 Trip Cost 或 Shortfall
- [ ] 假期不足而被排除的國家不高亮，與清單的行為一致
- [ ] 視覺化為清單的補充而非取代——清單仍是比較金額的主要方式
- [ ] 手機上可用，不因此犧牲 08 的成果
- [ ] 不得為了視覺化而把邏輯搬進 UI 層，`planTrips` 維持唯一接縫
